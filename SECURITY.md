# Security Policy

## Supported versions

Security fixes are generally developed against the current development branch and the latest project release. Older releases may not receive security fixes. Users should update to the latest compatible release where possible.

Xray Extender depends on OpenWrt, LuCI, and Xray. A security issue may belong to one of those upstream projects rather than to Xray Extender itself; reports are still welcome when the affected component is unclear.

## Reporting a vulnerability

Please do **not** report security vulnerabilities through public GitHub issues, public discussions, or pull requests.

Use GitHub's **Private vulnerability reporting** feature for this repository when it is enabled. It provides a private channel for sending vulnerability details to the maintainers.

If private vulnerability reporting is unavailable, contact the repository owner or maintainer privately through an available GitHub contact method and ask for a secure reporting channel. Do not publish exploit details while arranging contact.

When reporting, include the affected version, relevant environment details, impact, and concise reproduction steps or a proof of concept where safe. Remove credentials, subscription URLs, private keys, tokens, and personal data from all attachments and logs.

## Response expectations

The project is maintained on a best-effort basis. There is currently no guaranteed response time, remediation deadline, or formal security-support commitment. The maintainers will assess reports as their time and the severity of the issue allow.

Please allow maintainers a reasonable opportunity to investigate and prepare a fix before publicly disclosing an unpatched vulnerability.
